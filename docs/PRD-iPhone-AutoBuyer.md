# iPhone AutoBuyer：简单地准备一次官网购买

更新：2026-10-12。按 [create-prd](https://github.com/phuryn/pm-skills/blob/c68487d721e419ec87af1ae6412a842978eab785/pm-execution/skills/create-prd/SKILL.md) 编写。

## 1. 概要

为使用 Mac、希望提前准备 Apple 中国大陆官网购买的人提供一个小工具。当前目录只保留官网实际出现的 iPhone 17、18 系列和 Duo。用户选机型、颜色、容量、门店和付款方式，软件准备官网入口和会话。

## 3. 背景

用户反馈旧界面要求填写链接、技术选项名称和重复金额，不知道从哪里开始。Duo 的官网已公开颜色、容量、价格及预购提示，却尚未开放下单。频繁刷新、官网拥堵和明确访问限制需要不同处理。

## 4. 目标

- 选择 Duo 时，填写商品链接、预算及技术参数的次数均为 0。
- 官方公开的型号与配置进入本机目录；Pro 与 Pro Max 的选择和价格分别保存。
- 维护、503 拥堵、排队、加载中和 429/541 拒绝的验收场景分别通过，结果未知的订单不能重复提交。

这些是本轮软件验收标准，不是对未来首发成功率的预测。

## 5. 用户与任务

**准备首发的人**：希望提前选择 Duo，登录一次，开售时减少找链接和填表。

**先验证流程的人**：希望用在售 iPhone 检查门店、取货人及付款步骤，再决定真实购买。

当前为中国大陆单账户、自提路径。银行付款仍由本人完成。

## 6. 价值主张

| 项目 | 准备首发 | 验证流程 |
|---|---|---|
| 谁 | 不想研究协议与参数的 Mac 用户 | 想先确认工具能否走通官网的人 |
| 为什么 | 开售时重新登录、找链接和选配置浪费时间 | 本地模拟不能证明真实官网兼容 |
| 以前 | 手动收藏链接，开售时不断刷新 | 只看演示，或冒险直接提交订单 |
| 怎样 | 官网目录缓存、中文选择、保持浏览器会话、按页面状态检查 | 明确的官网试跑，真实页面状态与人工接管提示 |
| 之后 | 购买条件和登录提前就绪 | 清楚知道已验证到哪一步 |
| 替代方案 | 手动浏览器、Apple Store App；本工具便于统一准备和日志 | 官网手动试跑；本工具保留可重复检查与订单锁 |

让用户先准备好购买条件，软件负责查入口和等待；用实际官网结果帮助用户判断，不把缓存、库存可选或模拟订单当成购买成功。

## 7. 方案

### 7.1 使用流程

选机型 → 选颜色与容量 → 选门店 → 选择付款与授权 → 登录 → 官网试跑 / 等待开售 → 官网核对 → 对应订单付款码。

### 7.2 本轮必须有

- 五个当前官网型号选择，提前读取配置和价格；更新只读取公开页面。
- 无链接的计划只等待官网实际发布的唯一入口，不生成 SKU。
- 删除手动预算输入，显示已公布价格；未读到金额或金额变化时，用金额明确的按钮确认。
- 首选付款、备用方式和期数均可点选；隐私同意书在官网查看，处理后点按钮继续。
- 单会话串行。维护与拥堵有节奏检查，真实排队不刷新，正在加载不打断；拒绝冷却跨重启保留。
- 订单只提交一次；金额、数量、商品、门店和付款方案仍核对。试跑不自动提交。

### 7.4 尚未证实的部分

Apple 没有公开本机适用的“安全刷新频率”或 541 原因。网上首发体验有矛盾，不能推出某个间隔必胜。Duo 尚未开放，公开配置正确不能证明它的结账及自动提交已适配。账户会话与验证码期限由官网决定。

## 8. 交付

本次交付为 macOS 应用、源码、官网目录快照、验证记录和私有 GitHub 仓库。首发当天的真实拥堵、Duo 结账及银行付款需按实际页面继续验证；本次不新建真实订单来填补这些证据。
