# IA ONE 到货下单

控制台的「IA ONE 到货下单」在当前配置页等待库存事件，无需 Codex、AI 对话或定时任务参与。

1. 选择商品颜色、容量、自提门店优先级和付款方案，保存取货资料及自动提交设置。
2. 「连接 IA ONE…」保存集成令牌一次；IA ONE 关注列表必须包含相同 SKU。
3. 提前登录所选浏览器，点击「IA ONE 到货下单」。软件配置好商品后停在当前页面，不提前加购。
4. 收到当前 SKU、中国大陆且包含允许自提门店的 `restocked` 事件，复核当前配置后直接进入购物袋，继续结账、自动提交与付款码提取流程。此路径不打开商品页的自提库存弹窗。

监听使用 [IA ONE 官方集成接口](https://iaone.app/integrations)的持续长轮询。每个请求最长等待 50 秒，事件到达立即返回，接着建立下一次等待；没有每分钟唤醒 AI 的间隔。正常无事件时不刷新 Apple 商品页，也不重复输出状态。软件退出、电脑睡眠或断网时无法保持实时接收。

`test`、售罄、其他 SKU、其他地区、纯线上配送、没有明确可用门店和超过五分钟的旧事件不会触发购买。其他门店按保存的「允许其他门店」设置处理。信号只是进入官网核验的条件，不代表库存已经锁定。Apple 验证码、排队和访问限制仍由正常网页流程处理。

提前保存的是门店优先级，不是已确认的取货门店或时间。进入结账后才读取当前门店与时段，选择符合日期设置的允许门店及第一个可用签到时段；已有有效时段保留。门店保存后延迟出现的时段控件和选项直接观察 DOM，不重选门店或反复进入库存弹窗。某家店有货但没有可用时段时，继续尝试下一家允许的门店。

全部允许的门店与时段都不可用时，按缺货设置停止或保留同一个购物袋等待下一次信号。等待期间不轮询 Apple；新信号到达后只正常刷新当前结账取货页一次，重新核对当时可用的门店与时段，不回商品页、不移除商品、不重新加购。缺少门店、时段格式变化、验证码或访问限制不能当成售罄反复重试。

此模式立即准备并等待到货，不使用已保存的开售预约；原预约时间保留，普通「开始抢购」仍使用它。运行中使用配置副本，编辑只影响下次启动。「停止任务」停止监听，保留浏览器会话。完成一次购买后本次监听结束，购买计划的持久提交锁防止重复下单；开始另一笔购买需要新计划。

令牌经本机现有 Fernet 密钥加密存入 `private-inputs/iaone.enc`，不进入购买配置、导出和日志。IA ONE HTTP 请求使用独立的 API 上下文，既不获取 Apple Cookie，也不向 Apple 发送 IA ONE 令牌。事件进度、待处理信号和已交接的事件编号原子保存到本机 `iaone-state.json`；连接失败保留进度，重连补读。连续三次连接失败提示一次，正常恢复再更新状态。

控制台记录「本机交接」耗时，起点是本机收到事件，终点是交给购买流程；不包含 IA ONE 在上游发现库存的时间，也不代表下单完成时间。付款仍由本人完成。

此功能不调整 Surge、VPN、代理或系统网络设置。代理调度方案可以另行接入，但它与库存接口、账号限制是不同层面；已登录的结账会话保持稳定出口更容易排查。减少查询不能保证官网不会拒绝访问。

Mac 和 Windows 共享同一服务代码。Windows 的网络环境、浏览器连接和安装包仍需在 Windows 机器验收。
