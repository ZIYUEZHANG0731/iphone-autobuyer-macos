# 自动化路线判断

更新：2026-10-13（北京时间）。结论基于当前软件代码、实际试跑记录及下方官方资料。

终端和图形界面只是操作入口。当前 CLI 和 GUI 使用同一自动化引擎，因此换成终端不会自动缩短 Apple 的响应时间。真正需要比较的是页面操作、HTTP 请求，以及等待条件。

| 路线 | 能省掉什么 | 需要验证什么 | 当前判断 |
| --- | --- | --- | --- |
| 屏幕坐标或图像识别 | 部分手工操作 | 分辨率、遮挡、布局变化 | 不作为官网购买的主要方式 |
| 浏览器内读取页面结构并操作控件 | 人的查找、判断、输入时间 | 控件名称、状态变化、页面加载与会话 | 当前登录及结账的可维护基础 |
| 直接调用 HTTP 接口 | 部分页面渲染及控件操作 | 接口契约、动态参数、登录状态、服务器处理结果 | 可能更快，需要逐项验证，不能仅凭终端外观判断 |
| 浏览器会话结合结构化响应 | 部分重复页面查询 | 数据与当前会话、商品和时间是否匹配 | 适合逐步评估的方向 |

## 本版实际使用的方式

购买流程通过 Playwright 或内置浏览器读取页面控件及语义标签，不使用屏幕截图逐步识图。供货区域更新观察页面正常操作引发的请求完成，再核对可见门店结果；没有手写重放 Apple 私有下单请求。

v0.7.1 将结账阶段控件集中读取，并使用 `MutationObserver` 在页面变化时返回。500 毫秒是一次观察的最长分片，变化满足条件时立即返回；分片用于响应停止任务。控件等待的 8/15/30 秒同样是超时上限，条件满足后立即继续，不是每步固定休眠。商品目录提前读取官网公开 HTML 中的 SKU 配置链接，按颜色、容量和官网价格对应具体配置；Pro / Pro Max 另保存机型选择。完整配置匹配唯一链接时直接打开，仍读取实际选中控件，已正确选中的控件不重复点击。

这次已确认的隐私卡点来自声明匹配和等待：软件预存“所必需的数据”，官网实际显示“所必要的数据”，并在链接旁附带辅助文字；游客按钮在隐私弹窗下仍可见。门店阶段的真实名称则带“2 Apple 南京东路”这样的序号。它们是软件识别和流程控制问题，换成终端仍需修复。

最终安装版 v0.7.1 / build 31 已在真实现货试跑中自动完成隐私确认、核对南京东路门店并继续，37.58 秒到达明确的取货人表单。这次关闭了个人资料填写，在姓名、联系方式和证件后四位字段前停止，未提交订单。这个结果验证当前卡点已推进，不能代替完整下单或首发速度对照；详细证据见 [验证清单](VERIFICATION.md)。

## 速度如何判断

比较同一网络、同一浏览器会话、同一商品和门店下的阶段耗时，区分：官网响应时间、控件就绪时间、软件读取与执行时间、验证码或人工等待。一次现货成功不能证明首发拥堵时的优势。

先移除重复读取和固定等待，明确暂停原因；再评估是否能从已发生的正常响应直接读取同等结果。直接 HTTP 下单需要另外验证完整流程，尤其是动态参数、失败后的状态判断以及是否已经创建订单。共享 Cookie 并不能证明请求已满足 Apple 的全部认证和结账条件。

按用户本次明确要求，两个 Apple 中国大陆结账隐私选项默认自动同意，不再比较整段正文或声明版本，软件的二次确认窗口已移除。范围包含购物袋已核对并点击游客继续后的商店登录入口，不能只按 `/shop/checkout` 路径判断，否则实际游客弹窗会被遗漏。不自动操作背景中的其他勾选框。控件不可用或出现其他选择时保留页面并显示诊断。

## 资料及判断边界

- [Playwright 自动等待](https://playwright.dev/python/docs/actionability)：操作等待控件可见、启用及接收事件等条件，条件满足后执行。
- [Playwright 页面等待](https://playwright.dev/python/docs/api/class-page#page-wait-for-timeout)：建议用网络事件或控件状态判断就绪，避免固定时间等待。
- [Playwright 网络响应事件](https://playwright.dev/python/docs/api/class-page#page-expect-response)：支持观察正常页面动作的响应。
- [Playwright APIRequestContext](https://playwright.dev/python/docs/api/class-apirequestcontext)：与浏览器上下文关联的请求可以共享 Cookie；这说明可以结合两种方式，不代表 Apple 支持任意直接请求。

这些是自动化工具能力的官方说明，不是 Apple 首发下单接口或性能承诺。当前没有对照实验能证明本软件在首发期间比手工购买更早进入官网；接口路线的潜在收益仍是工程判断。
