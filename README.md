# iPhone AutoBuyer for macOS

Apple 中国大陆官网 iPhone 17、18 系列与 Duo 的购买准备、真实网站试跑与受条件保护的下单工具。Python / PySide6 / Playwright，Apple Silicon。

**v0.4.0**：直接选择机型、颜色、容量、门店和付款；不用填写链接、技术选项或预算。目录已从官网读取 Duo、17、17e、18 Pro、18 Pro Max，并分别保存真实配置和价格。官网价格变化或未读到时用金额明确的按钮确认。Duo 的官网开售时间可一键填写。

使用正式 Chrome 的软件独立会话和正常默认设置，提前登录后保持打开。维护、拥堵、加载和排队与明确拒绝分别处理。当前界面与验收见 [产品需求与迭代](docs/PRODUCT_REVIEW.md)、[发布前自查](docs/PreMortem-iPhone-AutoBuyer-2026-10-12.md)、[验证清单](docs/VERIFICATION.md)。

![原生商品选择界面](docs/images/product-v040.png)

**实际验证边界：** 2026-10-11 已在真实 Apple 官网，经用户授权创建 1 个 iPhone 17 白色 256GB、RMB 6,799、招商银行 24 期的待付款订单，并提取真实付款二维码。该完整订单验证通过 Codex 浏览器完成；软件独立 Chrome 的真实供货查询已在 2026-10-12 连续通过，登录、试跑和首发验证按 [验证清单](docs/VERIFICATION.md) 分别记录。不能把库存成功等同于首发或全品类自动下单成功。

最终安装版 v0.4.0 / build 8：**145 项测试通过**，真实登录及本次重启恢复已确认；现货试跑 20.27 秒到达 Apple 数据隐私协议，等待本人确认。未在这次试跑创建新订单；后续结账与尚未开售的 Duo 不宣称已经通过。

## 启动

已安装的本机应用：`~/Applications/iPhone AutoBuyer.app`，可通过 Finder 双击。首次使用在「诊断…」中点击「检查环境」；正式 Google Chrome 已安装时直接使用软件独立会话；没有 Chrome 且 Chromium 缺失时点击「安装浏览器」。准备检查也能直接定位这些操作。

源码启动：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m app.main
```

也可双击 `scripts/run.command`，需要事先安装依赖。

## 使用流程

1. 商品配置：直接选机型、颜色、容量和数量，点击「保存商品」。官网入口和已公布价格由目录准备；「更新官网型号与配置」读取当前公开页面。不猜未发布 SKU，也不把公布的价格当成有货。
2. 自提门店：设置省、市、区，从官网查询门店；添加允许门店，拖动决定优先顺序，勾选启用。列表外备用门店须单独允许。不会自动改为邮寄。取货日期限制无法在最终页面可靠确认时会暂停。
3. 取货人：使用 macOS Keychain 保存多组信息，设置默认取货人。当前实测表单分为姓氏、名字、邮箱、手机、证件后四位；可选择类型文字「居民身份证后四位」，仅保存四位。勾选「允许向 Apple …填写」后软件才会取出并填写。验证码、隐私协议和必要的身份验证由本人处理。
4. 付款与授权：下拉选择首选方式与期数，勾选备用方式并拖动排序；勾选需要的填写或提交授权后保存。方案仍须由实际结账页面确认。Apple 隐私协议在官网查看并选择，随后点软件的「已在官网处理，继续检查」。
5. 控制台：用「登录并保持会话」登录，再点「继续检查」。先用「官网模拟下单」检查在售商品，试跑不会点击「立即下单」。Duo 可点「使用官网开售时间」填入带时区的预约。真实购买前，准备清单会提示缺少的配置和取货人。
6. 软件检测到官网待付款确认页后，会提取唯一可见的付款二维码。用「查看付款二维码」查看，或「提取当前付款码」重读当前页面。付款窗口提供保存图片、复制图片和复制付款说明，方便由你转发给对应下单人；软件不会自行向别人发消息。
7. 「运行记录」分为运行阶段、门店变化、订单与付款码。门店列表显示上次检测结果、说明和检测时间，变化记录区分商品配置；旧结果不代表现在有货。多个历史订单可分别选中查看其付款码。

**当前自动提交条件：** 商品、全部已选配置、数量、最终总金额、允许门店及付款方案都必须可靠核对。真实提交适配目前限定已观察的招商银行 24 期路径。2026-10-11 实测 Review 页面不展示门店名称，并提示取货日期在付款后确定，因此该页面仍会暂停让你人工核对和下单。其他商品或付款路径需要实际验证，不能保证都可自动完成。

## 前一天登录与开售检测

- 使用「登录并保持会话」在软件打开的 Chrome 登录 Apple，完成验证后点「继续检查」。随后浏览器保持打开，商品设置、门店检查和抢购共用这个浏览器进程，不会为了切换任务重新启动浏览器。首次改用 Chrome 时需要在此独立会话登录一次，旧 Chromium 与日常浏览器的登录不会复制过来。
- Codex 右侧浏览器、Safari、日常 Chrome 与本软件会话相互独立。软件不复制其他浏览器的 Cookie，也不导出登录令牌。
- 登录资料正常保存在私有浏览器目录，但关闭浏览器可能丢失会话 Cookie；前一天准备后建议保持软件和它的浏览器运行。
- 「停止任务」停止当前购买或检查，保留同一登录浏览器与进程锁。「关闭会话」或退出软件才关闭浏览器；本地测试和安装等独立任务没有需要保留的官网会话。
- 预约时间下方同时显示北京时间和柏林时间；切换时区只转换显示，保留同一开售时刻。过去的预约不能启动新真实购买，需更新未来时间或取消预约以立即开始。夏令时不存在或重复的时刻须重新明确设置。
- 控制台提供「检查登录状态」。真实抢购开始前检查一次；若有预约时间，开售前 10 分钟再检查一次。账户页维护或暂时无法连接时保留会话并显示「暂时无法复核登录」；真正退出登录会要求重新登录。Apple 可要求再次认证，本软件不能保证登录永久有效。
- 登录后的加载页不会直接判为未登录：最多观察 15 秒，不再次提交密码。登录返回请求出现关键 403/429/541 时立刻显示原因、保留浏览器并等待，不把页面转圈误报成账号错误。
- 预约时刻到达检查当前商品页。维护或普通连接失败持续检查：平时默认 10 秒起并逐步退避，预约开售后前两分钟默认 5 秒，均在上一次检查结束后计时。正在加载时继续观察，明确排队时保留页面，不打断或刷新队列。
- HTTP 503 拥堵与维护会按 `Retry-After` 自动等待；关键 403/429/541 则暂停，冷却至少 5 分钟，连续回合延长，服务器要求更久时从其要求。拒绝冷却跨重启保留，不能用重开任务跳过。541 的具体服务器原因未知，不等同于已证明封 IP；这些频率也不是 Apple 公布的最佳或保证安全参数。
- 访问受限时「继续检查」显示等待倒计时，期限内不可用；停止任务后再启动检查也不会跳过等待时间。
- 自提无货时从设定间隔逐步退避，默认上限 60 秒。每次通过正常区域选择触发新查询，等浏览器请求完成和门店列表更新后才记录检测时间；未知查询入口会暂停。一个结果读取附近门店，不逐家重复进入结账。
- 初始网络连接失败不会立即放弃整个计划。维护页、未开放的预购页、商品可选、自提可选和真实订单确认分别处理。
- 新配置默认显示北京时间；已有配置保留原来的时区。时区选项只影响显示和预约换算，中国站地址、网络出口和账户地区不会随之改变。
- 「会话保持期间防止 Mac 自动睡眠」使用系统 `caffeinate`，在会话启动时生效，关闭会话/退出后释放。建议接电源；不能保证合盖、断网或系统强制睡眠时继续运行。
- 若官方提供提前准备/保存购物袋的入口，会显示检测结果；先在官网完成官方准备。不能把普通购物袋当作已创建的订单，也不会提前调用隐藏下单接口。

2026-10-11 官网观察显示 Duo 在 2026-10-16 晚 8 点（北京时间）接受预购，10 月 23 日发售。应在开售前再次核对官方通知。控制台可直接选择「北京时间」；同一时刻为柏林 10 月 16 日 14:00，内部仍按 `Asia/Shanghai` 换算。

## 付款码与订单锁

- 只截图官网确认页中可见的二维码图片，不截图整页联系人、证件信息，不保存解码后的支付链接/令牌。
- 每张图片关联订单号和已核对的商品/金额/付款方案；未知商品或金额会明确留空，不能用预算上限冒充实际金额。
- 官网给出的 30 分钟等相对时限必须结合已知提交时刻计算。人工创建的订单若没有可靠起算时间，显示「起算时间未知，请以官网为准」，不会每次提取都重新开始倒计时。
- 已知期限到达后隐藏图片，并禁用保存/复制图片。同一订单重新打开不会延长原有期限。扫码或保存图片不代表已付款。
- 自动提交前以 SQLite 原子写入订单锁。提交超时、停止或崩溃均保留锁，不会盲目重试。当前会话可等待其正常订单确认页；重启后须通过 Apple 正常订单页面人工核对旧订单。
- 一个购买计划对应一个 intent。已确认或结果未知的计划不重复下单；重新购买时在「付款与授权」点击「创建新的购买计划」，保留旧锁并重新确认购买授权。
- 不自动取消或修改已创建订单。
- 运行中的任务使用启动时的配置副本；之后修改商品、付款和授权只影响下一次任务。

## 数据位置

`~/Library/Application Support/Apple AutoBuyer/`

正式 Chrome 使用其中的 `chrome-profile/` 独立目录，通过仅本机可连接的受支持调试连接执行正常网页操作；正常退出会让浏览器自行保存资料。`browser-profile/` 为旧 Chromium 会话，保留但不复制其 Cookie。本机重启测试能保留有到期时间的合成 Cookie，不能据此承诺 Apple 的登录或结账永久有效。

- `autobuyer.sqlite3`：商品配置、门店、身份引用、阶段、脱敏结果、门店变化与订单锁；不含完整身份证、电话号码、邮箱或密码。
- `chrome-profile/`：正式 Chrome 的软件独立会话；目录权限 700。
- `browser-profile/`：旧 Chromium 资料，保留。
- `public-catalog.json`：已读取的公开型号、配置与价格；不保存账户或身份。
- `website-cooldown.json`：拒绝与临时繁忙的等待期限；不保存 IP、URL 或 Cookie。
- `payment-qr/`：付款二维码图片与订单元数据；目录权限 700、文件 600。图片含付款能力，只在本机保存，是否转发由你决定。
- macOS Keychain 服务：`com.autobuyer.apple.identities`。不采用纯文本 keyring 后端。

配置导出不包含身份资料；配置导入不授予填写身份或真实下单授权。日志和浏览器异常不会输出填写值。工程忽略二维码、私有测试报告、数据库、虚拟环境和构建产物。

## 测试

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m app.main --local-test all --headless --report reports/local.json
.venv/bin/python -m app.main --smoke-test --screenshot reports/gui.png
```

本地模拟商店只用于开发异常测试，使用合成身份、合成订单。覆盖首店/次店/无货、库存变化、缺失配置、付款不可用、身份缺失、维护、网络超时、提交超时、延迟成功、服务器拒绝、429 和停止。真实 Chromium 的离线 DOM 测试覆盖图片标签银行、分期期数、延迟出现的 AppleCare 选项、真实确认页结构、付款码裁取、单次提交保护以及跨任务保留会话 Cookie。

可选真实网站试跑（永不自动提交，也不加载身份）：

```sh
.venv/bin/python -m app.main --live-check --config scripts/stocked-example.json --report reports/live-check.json
```

真实网站试跑若出现限流会暂停，不以本地成功替代真实验证。

仅核验软件浏览器的公开商品供货读取（不加购、不结账、不读取身份）：

```sh
.venv/bin/python scripts/inspect_stock.py --checks 2 --interval 90 --output reports/apple-stock-software.json
```

该开发检查使用软件正常的浏览器与私有会话目录；本机已安装 Chrome 时采用软件独立 Chrome。`--wait-for-load` 仅用于对比等待完整页面加载的受控实验。v0.2.2 的几个独立自动化对照曾遇 541；v0.3.0 的程序已经连续两次读取 12 家门店供货（间隔 60 秒），报告为 `reports/apple-stock-repeat-20261012.json`。这项检查没有身份填写、加购或订单提交。

一次性的正式 Chrome 兼容性开发检查：

```sh
.venv/bin/python scripts/inspect_chrome.py --output reports/chrome-compat.json
```

只使用公开商品，使用临时独立目录；不会读取日常 Chrome 的资料、密码或 Cookie。该检查不改变生产浏览器配置。

## 打包

```sh
./scripts/build.command
./scripts/install.command
```

生成 `dist/iPhone AutoBuyer.app`，安装脚本复制到 `~/Applications`。更新已有本机 App 时先保留带时间戳的上一版。包内包含 Python、GUI、Playwright 驱动和模拟 HTML；Chromium 采用独立版本缓存，可通过 GUI 安装。构建仅为本机进行 ad-hoc 签名，不是公开发行的 Developer ID 公证包。

`prepare_plugins()` 处理此工作目录忽略文件被自动标为 Finder 隐藏后导致 Qt 发现不到 Cocoa 插件的问题，只调整软件自己的插件隐藏标记，不关闭系统安全保护。打包脚本清除生成 App 的 FinderInfo/ResourceFork 元数据后签名，不删除 quarantine。
